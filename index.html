02What this course is

It is two things at once. It is a course in advanced multimedia techniques: real-time and generative tools, sound, projection, sensors, and the workflows around them. It is also a portfolio course: by the end of the semester you will have a body of documented work and a live portfolio to put it in.

So treat the weekly sketches accordingly. They are small and meant to be fast, but a sketch you would happily show someone takes about the same evening as a sketch you would not. Push each one a little further than the brief asks, and make them varied: you want a portfolio with range in it, not twelve versions of the same instinct. By November you should be choosing which pieces to include rather than hunting for three that are presentable.

03This course and FMD 404

You are all in both, back to back, and they are built to work together. The tools you learn here are the tools your 404 projects will need, usually about a week before you need them. What is different is what each course asks of you: 404 is the studio, where the work is conceptual, developed over weeks, and reviewed as finished projects. This is the lab, where you learn techniques fast, in small pieces, weekly.

The only rule is that a thing submitted for a grade in one course is not submitted for a grade in the other: here I am grading the technique and its documentation, in 404 the project itself.

04This course is also yours

The demo list is a starting point, not a fixed menu. If there is a technique you want to learn, tell me and we will try to fit it in, even if it is something I cannot do myself. I have people around me who can, and bringing someone in for a workshop is easier than you would think.

07What I expect

  • Show up with the sketch made. Missing one is survivable, missing three is a different conversation.
  • Break things, since a sketch that failed interestingly is worth more here than a safe one that worked. Experiment as much as you can: playing it safe is not the way through this course, and the work that goes wrong in an interesting direction is usually the work worth developing.
  • Ask early. Two hours stuck alone on an install error is two hours you did not spend making something. Message me, search the forums, read the docs, ask the community. Worst case, ask an AI, but source it and make sure you understand what it hands back before you use it. Code you cannot explain is code that will break in front of an audience.
  • Credit what you borrow. If you build on someone's patch, tutorial or code, say so. That is normal practice, and it is only a problem when it is hidden.
  • Copy and paste is fine. Creative coding runs on borrowed code, and every community you will use publishes its examples for exactly this reason. Three conditions: credit the source, understand what every line is doing, and treat it as a starting point rather than the finished thing. Pasted code that you then bent into something of your own is the whole method. Pasted code you cannot explain is a problem waiting for a crit.
  • Back up your work. Browser-based tools store sketches locally, which means one cleared cache can erase a month. Export regularly.

Demo 01

Hydra I · Signals

Live-coded video synthesis in the browser, made by Olivia Jack. Nothing to install. Sources flow through transforms into outputs, and every number can move. Today: the full signal vocabulary. Next session: systems: feedback, buffers, external sources, and performing.

Some lore before we start. In the 1960s, synthesizers were furniture: walls of modules (oscillators, filters, mixers) connected by patch cables, where sound was a voltage you could physically re-route. Video artists built the same idea for images: machines like the Sandin Image Processor and Rutt/Etra scan processor bent the TV signal itself, live. Hydra, made by Olivia Jack in 2018, is that whole room of machines compressed into a browser tab: the functions you chain today are patch cables, and modulate is literally one signal plugged into another's input.

01The editor

Open hydra.ojack.xyz. Run the current line/block: ctrl+enter. Run the whole page: ctrl+shift+enter. Clear all visuals: run hush(). Hide/show the code: ctrl+shift+h. Random example: the dice button; read those examples like flashcards, one line at a time.

02Sources: your raw material

hydra
osc(10, 0.1, 1.2).out()    // oscillator: frequency, sync (scroll speed), color offset
noise(4, 0.2).out()        // perlin field: scale, speed
shape(3, 0.4, 0.01).out()  // polygon: sides, radius, edge smoothing
gradient(0.4).out()        // rgb gradient cycling at speed
voronoi(8, 0.5, 0.2).out() // cellular pattern: density, speed, blending
solid(1, 0.2, 0.1).out()   // flat color: r, g, b

Six sources are the entire alphabet. Everything else is what you do to them.

edit the code, then run it

03Geometry transforms

hydra
osc(20, 0.05, 1.3)
  .rotate(0.4)          // radians; try Math.PI/4
  .scale(1.5)           // >1 zooms in, <1 tiles out
  .pixelate(40, 40)     // mosaic resolution x, y
  .repeat(3, 2)         // tile: x times, y times
  .kaleid(5)            // mirror segments
  .scroll(0.1, 0)       // wrap-around movement x, y
  .out()

Comment lines in and out with // and re-run: this is how you learn what each one owns. invert(), posterize(4), thresh(0.5), luma(0.4) live on the color side: try each alone.

04Color as a channel

hydra
noise(3, 0.1)
  .color(1.2, 0.4, 0.3)     // multiply r, g, b
  .saturate(2)
  .contrast(1.4)
  .brightness(0.05)
  .hue(0.2)
  .out()

// negative numbers are legal and strange: color(-1, 1, 0.5)

05Blending: two signals, one screen

hydra
osc(10, 0.1, 0.9)
  .add(shape(4, 0.3).rotate(0.3), 0.6)   // light: sum, amount 0-1
  .out()

osc(10).mult(shape(24, 0.6, 0.4)).out()  // mask: shape cuts the osc
osc(10).diff(osc(9).rotate(0.1)).out()   // interference between near-twins
osc(10).blend(noise(3), 0.4).out()       // crossfade at 40%
osc(10).layer(shape(3).luma(0.4)).out()  // stack with transparency via luma
osc(10).mask(shape(2, 0.5, 0.2)).out()   // hard stencil

Photoshop blend modes, live. diff between two slightly different oscillators is the classic moiré trick: near-identical signals produce the richest interference.

06Modulate: signals bending signals

hydra
osc(30, 0.1, 1)
  .modulate(noise(3, 0.2), 0.4)   // noise pushes the osc's pixels
  .out()

// each transform has a modulate twin:
osc(20).modulateRotate(osc(4), 0.6).out()
osc(20).modulateScale(shape(3), 0.4).out()
osc(20).modulateKaleid(noise(2), 4).out()
osc(20).modulatePixelate(noise(5), 100).out()
voronoi(6).modulateScrollX(osc(2), 0.2).out()

Modulation is where Hydra stops being stripes. The second signal is invisible; only its influence shows. Ask of every patch: what is seen, and what is only felt?

edit the code, then run it

07Numbers that move by themselves

hydra
// any parameter accepts a function of time:
osc(() => 10 + Math.sin(time) * 8, 0.1, 1).out()

// or an array: hydra steps through it to the beat
osc([10, 40, 80], 0.1, [0.5, 1.5]).out()

// array methods shape the rhythm:
shape([3, 4, 5, 6].fast(2), 0.4).out()      // twice the speed
osc(30, 0.1, [0, 1.5].smooth()).out()        // glide, not step

time is a global clock in seconds. () => makes any parameter a living function; arrays make it a sequencer. This one idea turns a still patch into a composition.

08Mouse as modulator

hydra
osc(20, 0.05, 1)
  .modulate(noise(3), () => mouse.x / width)
  .rotate(() => mouse.y / height * 3.14)
  .out()

Demo 02

Hydra II · Systems

Session two: Hydra as an instrument. Feedback, the four output buffers, external sources (camera, video, screen, images), writing your own functions, resolution and recording: everything you need to move from patches to pieces, and to perform live.

01Feedback: the screen remembers

hydra
src(o0)
  .scale(1.01)
  .rotate(0.003)
  .blend(osc(6, 0.1, 1.4), 0.08)
  .out(o0)

src(o0) reads the output back in: each frame inherits the last, scaled slightly. Change scale(1.01) to 0.99: the trail falls inward instead of out. The blend amount is the ink flow: lower = longer memory.

02Feedback recipes

hydra
// echo trails on a moving shape
shape(4, 0.2)
  .scrollX(() => Math.sin(time) * 0.3)
  .layer(src(o0).scale(1.03).luma(0.1).color(0.9, 0.9, 0.9))
  .out(o0)

// smear: modulated feedback
src(o0)
  .modulate(noise(4, 0.1), 0.008)
  .blend(shape(3, 0.3).rotate(() => time * 0.2), 0.04)
  .out(o0)

Two families: transform feedback (echo, zoom, spin) and modulated feedback (smear, melt). Every video-feedback piece you have ever seen is one of these two with taste.

03Four buffers: o0 to o3

hydra
osc(20, 0.1, 1).out(o0)          // build in separate buffers
noise(4).thresh(0.6).out(o1)

src(o0).mult(src(o1)).out(o2)    // combine them in a third

render(o2)                        // show one buffer fullscreen
// render() with no argument: all four in a grid: your mixing desk view

Buffers are layers you can keep working on independently: a background system in o0, a mask in o1, the mix in o2. render() alone is how you monitor everything while performing.

04External sources: s0 to s3

hydra
s0.initCam()                    // webcam
s1.initImage("https://upload.wikimedia.org/wikipedia/commons/2/25/Hydra-Foto.jpg")
s2.initVideo("myclip.mp4")      // a hosted mp4 url
s3.initScreen()                 // capture another window: browser asks which

src(s0)
  .modulate(src(s0).scale(1.01), 0.01)  // camera modulating itself
  .saturate(1.3)
  .out()

initScreen() is the sleeper: capture a browser tab playing your own footage, a p5 sketch, or a video call, and Hydra becomes a live effects processor for anything on your machine. This is also the bridge for footage: host clips (GitHub works) and pull them with initVideo.

05Write your own transforms

hydra
// a reusable look, defined once:
const vhs = (sig) => sig
  .saturate(0.7)
  .contrast(1.2)
  .modulateScrollX(noise(1, 0.5), 0.003)
  .blend(noise(30), 0.06)

vhs(src(s0)).out()               // apply to camera
vhs(osc(10, 0.1, 1)).out(o1)     // or to anything

JavaScript functions bottle a look. Build a personal library of three or four: your grade, your texture, your glitch: and every performance starts from your own voice instead of defaults.

06Resolution, speed, quality

hydra
setResolution(1920, 1080)   // match your output/projector
speed = 0.5                 // global clock multiplier
bpm = 120                   // array stepping tempo

07Recording and performing

  • Record: screen-record the tab (macOS cmd+shift+5) or capture the tab in OBS for clean 1080p.
  • Perform: hide code with ctrl+shift+h, or keep it visible: live coding shows the instrument, and audiences love it.
  • Prepare a set: one text file, patches separated by comments, run block by block. Improvise the numbers, not the structure.
  • Fullscreen on a projector: this is already projection-ready: demo 09 picks this up.
Study session: pick one artist performance from the hydra community (the hydra garden links out) and reverse-engineer one moment of it in your own patch.

Demo 03

Hydra III · Type + Sound

Two upgrades to your instrument: words become sources, and the microphone becomes the new mouse. Then the two meet: sound that moves type. Everything here runs in the same editor with the same rules you already know.

01The extension

Hydra has no text button, because Hydra only understands signal. So we turn a word into an image and load it as a source. The community already built this properly: hydra-text, an extension by geikha. Same rule as always: we use it, we credit it, we understand roughly what it does.

hydra · run this first, on its own
await loadScript("https://cdn.jsdelivr.net/gh/geikha/hyper-hydra@latest/hydra-text.js")

This is line one of every type patch. It pulls the extension into your Hydra for this session only: refresh the page and it is gone. If you ever see text is not defined, this line did not run.

02First words

hydra
text("LOOP").out()          // filled word, auto-sized to the screen
strokeText("LOOP").out()    // outlined word

These are sources, like osc and noise. They start chains, they can never sit in the middle of one, and everything you have ever done to a source works on them:

hydra
text("LOOP").kaleid(4).out()
text("LOOP").pixelate(30, 30).out()
text("LOOP").rotate(() => mouse.x / width).out()

Run each line on its own (cursor on the line, ctrl+enter). They all end in .out(), so whichever you ran last owns the screen.

Two more variants exist: fillStrokeText() draws the outline over the fill, strokeFillText() the fill over the outline.

03The control panel

All the typographic decisions live in one settings object called hydraText. Change a setting once and every text after it obeys:

hydra
hydraText.font = "Georgia"        // any font installed on your machine
hydraText.fontStyle = "bold"      // normal, italic, bold, bold italic
hydraText.fontSize = "auto"       // auto fills the width; "60%" of that; "200px" exact
hydraText.textAlign = "center"    // center, left, right
hydraText.fillStyle = "white"     // fill colour: any css colour name

For fillStyle, any named web colour works: the full list lives at MDN's named colours page. Keep it white when you plan to mask or mult the word with signal, since those tricks read brightness.

04Type as signal

Nothing new from here on. A word is a source, and everything from demo 01 applies to it. Run each patch separately: they all end in .out(), so whichever you ran last owns the screen.

hydra
osc(30, 0.05, 1).mult(text("LOOP")).out()   // mult: the word as a stencil, signal pours through

text("LOOP").modulate(noise(2, 0.3), 0.04).out()   // modulate: the letters breathe. 0.04 alive, 0.4 soup

noise(3).mask(text("LOOP")).out()           // mask: the hard-cut cousin

solid(0, 0, 0)                               // feedback: the word trails into itself
  .layer(text("LOOP"))
  .blend(src(o0).scale(1.01), 0.4)
  .out(o0)

The modulate amount is the legibility dial, and it is a typography decision: how far can a word move before it stops being a word?

05Build the big one

A real patch, built the way patches actually get built: one layer at a time, running after every step.

hydra · step 1: a word on a ground
solid(1, .2)
  .layer(text(" hydra_! "))
  .out()

solid(1, .2) is a deep red card, the word laid on top. The spaces inside the quotes are padding: they keep the word off the screen edges.

hydra · step 2: the ground remembers
solid(1, .2)
  .blend(src(o0).scale(1.02))
  .layer(text(" hydra_! "))
  .out()

src(o0) is the screen one frame ago, scaled up slightly, blended back in. Feedback: everything drifts outward and echoes.

hydra · step 3: the memory changes colour
solid(1, .2)
  .blend(src(o0).scale(1.02).colorama(.02))
  .layer(text(" hydra_! "))
  .out()

One new word: colorama rotates every colour a small step. Alone, barely visible. Inside a feedback loop it compounds every frame, so the wash climbs through the spectrum. .02 boils, .005 simmers: a number to perform, not to set.

hydra · step 4: the word fights its own outline
solid(1, .2)
  .blend(src(o0).scale(1.02).colorama(.02))
  .layer(text(" hydra_! "))
  .diff(strokeText(" hydra_! ").modulateScale(noise(1, 1), .4))
  .out()

diff against strokeText of the same word, warped by noise: the near-twin interference trick from demo 01, done typographically. Now change the word, the font, the colorama rate, the noise amount. Four dials, four different pieces.

One more dial: the ground itself. solid is just the quietest possible source. Swap it for any other and the whole piece changes character:

hydra · same patch, different grounds
osc(8, 0.05, 1.2)
  .blend(src(o0).scale(1.02).colorama(.02))
  .layer(text(" hydra_! "))
  .diff(strokeText(" hydra_! ").modulateScale(noise(1, 1), .4))
  .out()

// or try starting with:
// noise(3, 0.1)     a smoky ground
// voronoi(6, 0.3)   a cellular ground
// gradient(0.2)     a slow colour wash

06Sound: the buckets

Play music out loud, then run:

hydra
a.show()

Bars appear and jump with the music. What is happening: your microphone hears the whole room as one mixed-up rumble. Hydra sorts that rumble into buckets, from low sounds to high sounds. Each bar is one bucket, and its height is how full that bucket is right now.

  • Low sounds (bucket 0): kick drums, bass, thunder, a truck idling, the thump you feel in your chest.
  • Middle sounds (buckets 1 and 2): singing voices, guitar, piano, the body of most music.
  • High sounds (bucket 3): cymbals and hi-hats, the "s" in speech, keys jangling, hiss.

Try it with your mouth: hum low and the left bars rise; say "sssss" and the right bars rise; clap and several spike at once.

Bars first, always. If the bars are dancing, sound works and any problem is in your patch. If the bars are dead, stop patching: the microphone is not being heard (permission, or the wrong mic selected). This one habit answers "why is it not reacting" ninety percent of the time.

07The four setup lines

hydra
a.setBins(4)      // how many buckets: a.fft[0] lows ... a.fft[3] highs
a.setSmooth(0.8)  // how calmly the numbers follow: 0.4 twitchy, 0.95 syrup
a.setScale(8)     // sensitivity: bars too small, lower it; slamming, raise it
a.setCutoff(2)    // the floor: quieter than this counts as zero
  • Each bucket, a.fft[0] to a.fft[3], is a live number between 0 (that kind of sound is not happening) and about 1 (it is loud right now).
  • setSmooth is the most musical dial: it decides whether the piece twitches at music or moves with it.
  • setScale is per room. Your bedroom, the studio and the exhibition wall are all differently loud: re-tune it wherever the piece is shown. That is normal, not a bug.
  • setCutoff stops fan hum and chatter from trembling your visuals.

08The recipe

hydra
osc(20, 0.05, 1.1).scale(() => 1 + a.fft[0] * 0.4).out()

Remember the mouse: a plain number is an answer, decided once, and () => turns it into a question asked every moment. Last time the mouse answered. Now bucket 0 answers. Read the middle part in English: "every moment, check the bass bucket, start from size 1, let the bass add up to 0.4 on top."

The recipe for everything: normal + bucket × how much.

  • The normal is what the patch does in silence, its resting state. Forget it and the patch dies whenever the music stops.
  • The number in the square brackets picks which sounds to listen to.
  • The how much is the leash: the bucket only reports 0 to 1, and the multiplier stretches that into a useful range. In 4 + a.fft[3] * 5, silence gives 4 and the loudest highs give 9. Remove the multiplier and the reaction caps at 1: plenty for modulate, a whisper for kaleid or scale.

09One bucket, one job

hydra
osc(20, 0.05, 1.1)
  .modulate(noise(3), () => a.fft[0] * 0.6)   // lows melt it
  .kaleid(() => 4 + a.fft[3] * 5)             // highs fold it
  .color(() => 1 + a.fft[1], 0.6, 0.9)        // mids blush it
  .out()

When bass does one visible thing and the highs do another, the image feels like it is listening. When every bucket is wired to everything, it just shivers. Live numbers and plain numbers mix freely: in the colour line, only red has an arrow, so only red listens.

The mic hears the room, so it hears your speakers: play music out loud. Laptops sometimes muffle their own speaker sound, so a phone or external speaker next to the laptop reacts better. a.hide() puts the bars away.

p5.js · The Sketchbook

Hydra was a synthesizer: you plugged signals together and the machine made the image. p5 is a sketchbook: nothing exists until you draw it. Today we learn the basics, then build a brush.

01Where it came from

In 2001 Casey Reas and Ben Fry built Processing at the MIT Media Lab: a language that treated code as a sketchbook for artists rather than an engineering tool. In 2014 Lauren McCarthy rebuilt the idea for the web as p5.js, with a community known for being kind to beginners. When you type setup() and draw(), you are using a convention two decades of artists have thought in.

Work in the p5.js web editor. Make an account so your sketches save.

Keep p5js.org/reference open in a tab. Nobody memorises these functions. Looking things up is the job, not a sign you are behind.

02The two boxes

p5.js
function setup() {
  createCanvas(600, 600)
}

function draw() {
  background(245)
  circle(300, 300, 200)
}
  • setup runs once, at the start. It sets the stage: canvas size, and later your colour settings.
  • draw runs 60 times a second, forever. Everything inside is redrawn from scratch each time, whether or not anything changed.
  • circle(300, 300, 200) is x across, y down, then size. The numbers in the brackets are what the function needs, always in a fixed order.

Change the three numbers and run again. Your sketch is not a picture, it is a flipbook being drawn 60 times a second.

03The canvas is graph paper

0,0 is the top-left corner. X grows to the right, as you would expect. Y grows downward, the opposite of the graphs you drew at school, so y = 500 is near the bottom.

p5.js
circle(150, 150, 120)        // x, y, diameter
square(320, 90, 120)         // x, y, size
rect(90, 320, 200, 100)      // x, y, width, height
ellipse(430, 420, 160, 90)   // x, y, width, height
line(0, 560, 600, 560)       // x1, y1, x2, y2
triangle(300, 470, 250, 560, 350, 560)

Every shape wants its numbers in its own order, which is what the reference is for. Two words make sketches flexible:

p5.js
circle(width / 2, height / 2, 120)

width and height are filled in by p5 with your canvas size, so width/2 is always the centre. Typing 300 works today and breaks the moment you resize.

04Shapes p5 has never heard of

p5.js
beginShape()
vertex(100, 100)
vertex(400, 180)
vertex(500, 350)
vertex(250, 480)
vertex(120, 320)
endShape(CLOSE)

Connect the dots. beginShape() puts the pen down, each vertex(x, y) marks one corner and p5 draws a line from the last corner to this one, endShape() lifts the pen, and CLOSE draws the final line back to the start.

circle and rect are shapes p5 already knows. vertex is how you draw a shape it has never heard of, and there is no limit on how many points you use. curveVertex() does the same thing but curves through the points instead of connecting them with straight lines.

05Colour

p5.js
background(20)
noStroke()
fill(229, 35, 27)
circle(220, 250, 260)
fill(60, 120, 255, 120)
circle(380, 350, 260)
  • fill(r, g, b) takes red, green, blue, each 0 to 255. One number on its own is grey: fill(0) black, fill(255) white.
  • The fourth number is transparency. 120 out of 255 is half see-through, so overlapping shapes build up like ink.
  • fill is a setting that stays on, not a property of a shape. Everything drawn after it uses that colour until another fill changes it. That is why people write one fill at the top and wonder why everything matches.
  • Also: noStroke() removes outlines, stroke(255) sets an outline colour, strokeWeight(4) its thickness, noFill() leaves only the outline.

If you would rather think in hue than in three channels, put colorMode(HSB, 360, 100, 100) in setup. Then fill(200, 80, 90) is hue, saturation, brightness, and you can walk a gradient by changing one number.

06The mouse

p5.js
function draw() {
  background(245)
  noStroke()
  fill(21)
  circle(mouseX, mouseY, 50)
}

mouseX and mouseY are where your cursor is right now. Same two words you used in Hydra, except here you do not need the arrow: in Hydra you wrote () => to say ask this again every frame, and in p5 the whole draw block is already being asked again every frame.

07Move one line, it becomes a brush

p5.js
function setup() {
  createCanvas(600, 600)
  background(245)
}

function draw() {
  noStroke()
  fill(21)
  circle(mouseX, mouseY, 50)
}

background() inside draw wipes the screen 60 times a second, so you only ever see the newest circle: that is animation. background() inside setup paints once, at the start, so every circle stays: that is painting. One line, moved, and it is the biggest decision in p5.

08Let the mouse choose the colour

p5.js
function setup() {
  createCanvas(600, 600)
  background(20)
  noStroke()
}

function draw() {
  fill(mouseX / 3, 100, 255 - mouseX / 3, 80)
  circle(mouseX, mouseY, 50)
}

Same fill as before, except the numbers are no longer fixed. mouseX runs 0 to 600, so dividing by 3 gives 0 to 200: a number in the range fill wants. Move right and red climbs while blue falls. Your position on screen is now choosing the colour, which is the whole idea: one value driving another.

09Speed changes the size

p5.js
function draw() {
  let speed = dist(mouseX, mouseY, pmouseX, pmouseY)
  fill(mouseX / 3, 100, 255 - mouseX / 3, 80)
  circle(mouseX, mouseY, speed * 3)
}
  • pmouseX and pmouseY are where the mouse was on the previous frame. p5 remembers for you.
  • dist() measures the distance between two points. Distance between where the mouse was and where it is now equals how fast you are moving.
  • let speed = ... makes a labelled box called speed and puts that number in it, so you can write speed instead of typing it out again.

Draw slowly for a thin line, quickly for fat blobs. Pressure sensitivity with no hardware.

10Mirror it

p5.js
function setup() {
  createCanvas(600, 600)
  background(20)
  noStroke()
}

function draw() {
  let speed = dist(mouseX, mouseY, pmouseX, pmouseY)

  circle(width - mouseX, mouseY, s)

Same circle, four places. width is 600, so width - mouseX is the mirror position: mouse 100 from the left becomes 100 from the right. You did not draw that shape. You drew a squiggle, and a rule turned it into that.

11Type

p5 draws text with no extension needed, unlike Hydra. Anything you can do to a shape you can do to a word.

p5.js
function setup() {
  createCanvas(600, 300)
  textAlign(CENTER, CENTER)
  textSize(120)
}

function draw() {
  background(245)
  fill(21)
  noStroke()
  text("LOOP", width / 2, height / 2)
}
  • text(string, x, y) draws the word. It uses the current fill, exactly like a shape.
  • textAlign(CENTER, CENTER) sets which part of the text sits at that x and y. The default is the left edge and the baseline, which is why type usually lands somewhere you did not expect.
  • textSize(), textStyle(BOLD), textLeading() and textWidth(string) do what their names say. textFont() sets the typeface, covered in the next section.

The interesting move is to stop treating a word as one object. Split it into letters and give each one its own rule:

p5.js · one rule, every letter
let word = "TRANSLATE"

function setup() {
  createCanvas(600, 300)
  textAlign(CENTER, CENTER)
  textStyle(BOLD)
}

function draw() {
  background(245)
  noStroke()
  fill(21)
  let step = width / word.length
  for (let i = 0; i < word.length; i++) {
    let x = step * i + step / 2
    let d = dist(mouseX, mouseY, x, height / 2)
    let s = map(d, 0, 300, 140, 30)
    textSize(s)
    text(word.charAt(i), x, height / 2)
  }
}

word.charAt(i) pulls out one letter, and the loop places each at its own x. Every letter asks the same question, how far am I from the cursor, and answers differently. Swap textSize for a rotation and the word starts to fall apart:

p5.js · letters that turn
let word = "SOURCE"

function setup() {
  createCanvas(600, 300)
  textAlign(CENTER, CENTER)
  textSize(90)
}

function draw() {
  background(20)
  noStroke()
  fill(245)
  let step = width / word.length
  for (let i = 0; i < word.length; i++) {
    let x = step * i + step / 2
    let d = dist(mouseX, mouseY, x, height / 2)
    push()
    translate(x, height / 2)
    rotate(map(d, 0, 400, 1.2, 0))
    text(word.charAt(i), 0, 0)
    pop()
  }
}

Legibility is now a variable you control. How far can a word bend before it stops being a word is a typography question, not a coding one.

12Loading a font

p5 falls back to the browser default until you give it something better. There are two routes, and they are not interchangeable, so pick by what you plan to do.

Route A: the CSS way, for drawing text

Quick, no files to manage, and it works with any Google Font. In the p5 editor, open index.html from the file panel and paste the link tag from Google Fonts into the head:

index.html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Space+Mono:wght@400;700&display=swap" rel="stylesheet">

Then name it in your sketch, exactly as the family is written:

p5.js
function setup() {
  createCanvas(600, 300)
  textFont('Space Mono')
  textSize(90)
  textAlign(CENTER, CENTER)
}

function draw() {
  background(245)
  fill(21)
  noStroke()
  text("LOOP", width / 2, height / 2)
}

Any font the browser can see works this way, with no link tag needed if it is already on the machine. These are safe on every computer:

p5.js · always available
textFont('sans-serif')       // whatever the system uses, Helvetica or Arial
textFont('serif')            // Times or similar
textFont('monospace')        // Courier or similar
textFont('Georgia')
textFont('Courier New')
textFont('Verdana')
textFont('Times New Roman')

Use one of those while you are building and swap in the real typeface later. If a font silently does not change, the name is spelled wrong or the link tag did not load: there is no error, it just quietly falls back.

Route B: loadFont, for everything else

Needed the moment you want textToPoints, because that reads the actual outlines out of the file and a CSS font name gives it nothing to read.

There is no system-font shortcut here. loadFont('Georgia') fails, because loadFont wants a file and the browser will not hand over a font that is merely installed. You need an actual .ttf or .otf.

Two ways to give it one.

A file next to your sketch. On Google Fonts press Get font, then Download all, unzip, and find the .ttf inside. Velvetyne and most foundries give you .otf or .ttf directly. Drag the file into the sketch files panel in the p5 editor and call it by name:

p5.js
let font

function preload() {
  font = loadFont('SpaceMono-Regular.ttf')
}

function setup() {
  createCanvas(600, 300)
  textFont(font)
  textSize(90)
  textAlign(CENTER, CENTER)
}

function draw() {
  background(245)
  fill(21)
  noStroke()
  text("LOOP", width / 2, height / 2)
}

Or straight from a URL, which is what you need in editors with no file panel, like HY5LIVE. The server has to allow it, and jsDelivr does:

p5.js · font from a url
function preload() {
  font = loadFont('https://cdn.jsdelivr.net/gh/google/fonts@main/ofl/spacemono/SpaceMono-Regular.ttf')
}

That path is the Google Fonts repository mirrored by jsDelivr, so any family in it works: swap the folder and filename for another. Note that Google Fonts' own CSS links will not work here, because fonts.gstatic.com serves .woff2 and p5 can only read .ttf and .otf. Check the real path on GitHub before you rely on it, since some families are stored as variable fonts under a different folder.

  • preload() waits for the file before anything else runs. Loading a font in setup instead gives you a sketch that works sometimes, which is worse than one that never works.
  • The filename must match exactly, capitals and hyphens included. SpaceMono-Regular.ttf is not spacemono-regular.ttf.
  • .ttf and .otf only. The .woff2 files that fonts.gstatic.com serves will not load this way.
  • Here textFont takes the loaded object, with no quotes, rather than a name in quotes.
Short version: drawing words, either route works and the CSS one is faster. Doing anything with the letterforms themselves, you need loadFont and a real file.

Fonts are licensed work. Google Fonts and Velvetyne are free to use and redistribute. A commercial font you licensed for print is usually not licensed to be uploaded somewhere public, so check before you publish a sketch with one in it.

13Type as points

The technique worth stealing. textToPoints() takes a word and hands back the coordinates along its outlines, as a list. The letters stop being type and become positions you can draw anything at.

This needs route B from the previous section: a real font file loaded with loadFont, not a CSS font name.

p5.js · letters made of dots
let font, pts

function preload() {
  font = loadFont('SpaceMono-Regular.ttf')
}

function setup() {
  createCanvas(600, 300)
  noStroke()
  pts = font.textToPoints('TYPE', 0, 0, 200, { sampleFactor: 0.15 })
}

function draw() {
  background(20)
  fill(245)
  translate(60, 220)
  for (let i = 0; i < pts.length; i++) {
    let p = pts[i]
    let s = 6 + sin(i * 0.3 + frameCount * 0.05) * 5
    circle(p.x, p.y, s)
  }
}
  • preload() is a third special function alongside setup and draw. It runs before everything else and waits for files to finish loading, which is where fonts, images and data go.
  • textToPoints(word, x, y, size, options) returns an array of points. Each one has a .x and a .y.
  • sampleFactor is the density: 0.05 gives a sparse scatter, 0.5 packs them tight. This is the dial you will actually tune.
  • Once you have the points, the word is just a shape. Draw circles, lines, images, other letters.

Every point can answer a question, exactly like the grid in the loops section:

p5.js · points that respond
function draw() {
  background(245)
  fill(21)
  translate(70, 220)
  for (let i = 0; i < pts.length; i++) {
    let p = pts[i]
    let d = dist(mouseX - 70, mouseY - 220, p.x, p.y)
    let s = map(d, 0, 200, 22, 2)
    circle(p.x, p.y, s)
  }
}

Subtract the translate from the mouse position so both are measured from the same origin. Or feed the points into a single shape instead, and the word becomes one wobbling outline:

p5.js · one continuous line
function draw() {
  background(245)
  stroke(21)
  noFill()
  translate(60, 220)
  beginShape()
  for (let i = 0; i < pts.length; i++) {
    let p = pts[i]
    vertex(p.x + sin(frameCount * 0.03 + i * 0.2) * 6, p.y)
  }
  endShape()
}

To centre a word rather than guessing at the translate, ask the font for its bounding box first:

p5.js · centred
function genType(txt, size) {
  textSize(size)
  let b = font.textBounds(txt, 0, 0, size)
  pts = font.textToPoints(txt, -b.w / 2, -b.h / 2, size, { sampleFactor: 0.15 })
}

Then translate to the centre of the canvas and draw. Call genType() again from keyPressed() and the word changes live while the sketch is running.

HY5 · Hydra + p5 Together

You now have two tools that do opposite things. Hydra is a synthesizer, p5 is a sketchbook. HY5 bridges them, and the bridge runs both ways. Which way you point it changes what you can make.

01The tool

HY5 is by Ted Davis, the same person behind P5LIVE and basil.js. It loads hydra-synth and p5.js together in one page with both in global mode, so you write Hydra chains and p5 functions side by side and pass images between them.

Work in hy5live.teddavis.org, a minimal live-coding editor with everything already loaded. Nothing to install. HY5 is also built into P5LIVE as a library if you prefer that environment.

Use Chrome. HY5 stacks several full-size canvases, and Chromium handles it best. If your machine struggles, add H.pixelDensity(1) and pixelDensity(1) to drop the resolution.

02Order matters

There are three ways to wire the two tools together, and they are not interchangeable. Each one decides which tool has the last word on the image.

  • p5 into Hydra. You compose something exact in p5, then Hydra wrecks it. p5 gives precision, Hydra gives texture. The final image is a Hydra image.
  • Hydra into p5. Hydra makes the material, p5 decides where it goes. Use it as a fill, a texture on 3D geometry, or tiles in a grid. The final image is a p5 image, so it stays sharp and controlled.
  • Hydra into p5 and back into Hydra. Hydra generates, p5 shapes it, then a second Hydra instance processes the result. Three stages, and each one can only work on what reached it.

The thing to notice: whatever comes last is what you see, and everything before it has already been flattened into an image. Hydra cannot un-flatten a p5 shape back into geometry, and p5 cannot recover the signal that made a Hydra frame. Decide the order before you build, because it is not a setting you can flip at the end.

  • That namespace is why the last chain reads synth.src(synth.s0) rather than plain src(s0): the second instance keeps its own sources, outputs and functions so the two Hydras do not collide.
  • H.hide() hides the first Hydra, since you only want to see it through the torus. H2.zIndex(2) puts the second one on top of everything.
  • H2.save() saves a frame from the second instance if you bind it to a key.

Read the flow from the top: voronoi becomes a texture, the texture becomes a rotating object, the object becomes a source, the source gets fed back into itself. Change the order of those stages and you get a completely different piece, which is the point of this section.

TouchDesigner I · TOPs

Node-based real-time visuals: instead of writing code, you connect boxes with wires, and each box does one thing to the image. Today we build one patch together, start to finish, step by step. If you follow every step you will end with footage melting through noise, with trails, rendered to a video file.

Some lore. TouchDesigner comes from Derivative in Toronto, and its family tree runs straight to Houdini, the film-industry tool behind most Hollywood effects. It grew up in concerts and installations: stadium visuals, museum pieces, and stage shows for artists from deadmau5 upward run on TD networks. The wall-of-modules idea from the Hydra demo is literal here: every box is a module, every wire is a patch cable, and unlike a rendered video, the whole thing is alive at 60 frames a second.

01Setup (do this before class)

  • Go to derivative.ca → Download. Install like any app.
  • First launch asks you to create a Derivative account and pick a license: choose Non-Commercial (free). It covers everything we do.
  • Put one short video clip (any mp4, phone footage is fine) on your desktop: we will use it in step 04.

02Open TD and clear the stage

  • Open TouchDesigner. You see a network of example boxes: these are nodes (TD calls them operators).
  • Drag a box to select all of them (or ctrl+a), press delete. Empty grid: this is your patching space.
  • Move around: hold middle mouse and drag to pan, scroll to zoom. Practice for ten seconds: navigation is half of TD comfort.

03Make your first node

  • Double-click on empty space. A menu appears with tabs across the top: TOP, CHOP, SOP... These are node families. Stay on TOP: the family that carries images.
  • Click Movie File In. A node appears showing a default video (a banana; long story).
  • Click the node once to select it, press p: its parameters open. Every node has these: this panel is where all the knobs live. Press p again to close.

04Load your own footage

  • Drag your mp4 from the desktop and drop it onto the Movie File In node. The banana becomes your footage.
  • If it did not take: open parameters (p) and click the + next to File to browse for it.

05Wire your first chain

  • Double-click empty space to the right of your movie node → TOP → Level. A new node appears.
  • Every node has a small output dot on its right edge and an input dot on its left edge. Drag from the movie node's output to the Level node's input. A wire connects them: the image now flows through Level.
  • Select Level, press p: drag Brightness and Gamma and watch the image respond. This is your exposure control.
  • Add one more the same way: TOP → HSV Adjust, wired after Level. Drag Saturation and Hue Offset: this is your grade.

06See it big

  • Every node has a small circle in its bottom-right corner: the display flag. Click it on your HSV node: that node now fills the background of the network.
  • Rule for the rest of the semester: the display flag shows you any point in the chain: click along the chain to see what each node contributes.

07Melt it: Displace

  • Add TOP → Noise (a moving grayscale cloud). In its parameters, set Type to Sparse, and under the Transform page, drag Translate Z slowly: the cloud drifts. Type a small expression later; dragging is enough today.
  • Add TOP → Displace. It has two inputs on its left edge: wire your HSV node into the top input (the image) and the Noise into the bottom input (the force).
  • Open Displace's parameters: drag Displace Weight. At 0.02 your footage swims; at 0.3 it dissolves. This node is Hydra's modulate() as a box.

08Trails: the feedback loop

  • Add TOP → Feedback, wired after Displace.
  • Add TOP → Transform, wired after Feedback. In its parameters set Scale to 1.01 and Rotate to 0.2: tiny numbers, big consequences.
  • Add TOP → Composite. Wire Transform into its top input, and your Displace node into its second input. In Composite's parameters set Operation to Over.
  • Now close the loop: open the Feedback node's parameters. Find the Target TOP field: drag the Composite node itself from the network and drop it into that field.
  • The image begins to trail and spiral: each frame remembers the last. Adjust the Transform's scale/rotate: the trail changes direction and speed.

09Render a video file

  • Add TOP → Movie File Out, wired after Composite.
  • In its parameters: set File to where you want the video, and leave the codec at H.264 for tonight.
  • Click the Record toggle On. Let the patch run 45-60 seconds. Click Record Off. Your file is on disk: watch it outside TD to confirm.
  • For a still instead: right-click any node → Save Image.

Demo 07

TouchDesigner II · CHOPs + Instancing

Session two, same method: one guided build, step by step. First we make a patch move by itself with CHOPs (boxes that carry numbers instead of images), then we turn one shape into a thousand with instancing, and finally we send TD's output into other software.

01Meet the CHOP family

  • Double-click empty space → the menu → CHOP tab. These nodes carry channels: numbers changing over time. Their viewers draw graphs instead of images.
  • Add LFO. You see a wave scrolling: a number going up and down forever. In its parameters, set Frequency to 0.2: a slow breath.

02Make the number useful: Math

  • Add CHOP → Math, wire the LFO into it.
  • In Math's parameters, open the Range page: set From Range −1 to 1, and To Range 0 to 360.
  • The wave now travels 0→360: a rotation. Math is the translator between "a wave" and "a parameter's language": you will use it constantly.

03Wire the number to an image

  • Build a quick TOP chain beside it: Movie File In → Transform (drop your footage on the movie node like last week).
  • On the Math CHOP, click the small + on its bottom-right to activate its viewer: you can now grab the channel.
  • Drag the channel's name (chan1) out of the Math node and drop it exactly onto the Rotate field in the Transform's parameters. A menu pops: choose Export CHOP.
  • The Rotate field turns green: it is now owned by the signal, and your footage rotates with the breath of the LFO. Green = alive. Right-click a green field → Delete Export to take it back.

04Five parameters breathing

  • Repeat the export move with new sources: an LFO at a different frequency onto the Transform's Scale; a CHOP → Noise onto a Displace Weight; a Noise onto HSV's Hue Offset.
  • A patch where five parameters breathe at five different rates never repeats: that is your first genuinely generative TD piece. Add CHOP → Lag between any jittery source and its Math: it smooths the motion into something musical.

05Instancing: build the render rig

  • New area of the network. Double-click → COMP tab → add Geometry, Camera, and Light. Then → TOP tab → Render. These four are the standard 3D rig: Render draws what Camera sees.
  • Wire nothing yet: Render finds them automatically if they sit in the same network. Click Render's display flag: you see a gray torus: the default shape inside Geometry.

06Give it a simpler shape

  • Scroll into the Geometry node (zoom in until you enter it, or select it and press enter): inside lives the torus.
  • Delete it. Double-click → SOP tab → add Sphere. In its parameters set Radius to 0.05 0.05 0.05.
  • On the Sphere node, turn on its render + display flags (the small blue and purple dots on the node's right edge).
  • Press u to go back up. The Render TOP now shows one tiny sphere.

07One sphere becomes a thousand

  • Add CHOP → Noise. In its parameters, on the Channel page: set Channel Names to tx ty tz (three channels). On the Common page set Start 0, End 1000, so the noise is 1000 samples long: one sample per copy.
  • Select the Geometry COMP, press p, open its Instance page: turn Instancing On.
  • In Instance CHOP, drag your Noise CHOP into the field. Then set Translate X = tx, Translate Y = ty, Translate Z = tz (the menus next to each will list the channels).
  • The Render TOP now shows a cloud of a thousand spheres, positioned by noise.

08Make the cloud live

  • On the Noise CHOP's Transform page, drag Translate Z: the entire cloud reorganizes itself smoothly. Export an LFO onto that parameter (the step 03 move) and the cloud breathes on its own.
  • Composite the Render TOP over your footage chain from step 03: generated cloud + your image: the mixed media rule inside one patch.

09Send TD anywhere: Syphon / Spout

  • Add TOP → Syphon Spout Out (that one node handles Syphon on macOS and Spout on Windows), wired at the end of your chain.
  • Your patch is now a live video source that other software can see: MadMapper, OBS, Resolume all list it as an input. This is how a TD patch reaches a projector rig, a stream, or another artist's machine (NDI In/Out TOPs do the same over the network).

10Show it properly

  • Press F1: Perform Mode: fullscreen output with the editor hidden. esc returns to the network. This is how TD pieces are actually shown, and how you record clean documentation of them.
  • Keep an eye on the frame rate in the bottom bar: below 45, something is too heavy: usually a Blur at full resolution or a huge Noise. Lower the resolution on that node's Common page.

Sound + Audio-Reactivity

Sound as material, then sound as signal: this demo wires audio into all three tools you now know: Hydra, p5, and TouchDesigner: the same idea three times: analyze the sound into numbers, map the numbers to visual properties, and mean it.

Some lore. In 1940s Paris, Pierre Schaeffer started making music from recordings of trains and doors: musique concrète: the idea that any captured sound is material. Around the same time, animators like Norman McLaren drew directly onto the optical soundtrack of film strips: images that literally became sound. Audio-reactive visuals are the same marriage from the other direction: sound analyzed into numbers, numbers made visible.

01Capture and shape (quick, but not optional)

  • Get close: distance is the enemy, not the microphone. Phone recorders at 30 cm beat good mics at 3 m.
  • Record 10 seconds of room tone wherever you record: it glues edits.
  • Levels peak around −12 dB, never 0: clipping is unfixable, quiet is fixable.
  • Edit in Audacity / Fairlight / Audition: fade every cut (even 5 ms), layer ambience under details, export WAV for work, normalize to −1 dB last.

02The two numbers every tool extracts

Amplitude: how loud right now: one number: good for size, opacity, weight. Spectrum (FFT): how loud per frequency band: an array: bass, mids, highs as separate signals. Every audio-reactive piece ever made maps these two onto visual properties: the craft is entirely in the mapping.

03Hydra hears

  .out()

  • 2. Click index.html. You are looking at the page that hosts your sketch. Find the lines that start with <script src=: those load libraries.

function setup() {

02How a breadboard works (30 seconds)

  • The two long rails down each side (marked + and −) are each one connected strip: power highways.
  • Every short row of 5 holes in the middle is connected across, interrupted by the center trench.
  • So: push the ESP32 across the trench, feed the + rail from its 3.3V pin and the − rail from GND, and any sensor leg pushed into the same 5-hole row as a jumper wire is connected to it. That is the entire theory.

03Software setup, exactly

  • 1. Download the Arduino IDE from arduino.cc/en/software and install it. This is where you write and upload code to the board.
  • 2. Open it → Tools → Board → Boards Manager → search esp32 → install "esp32 by Espressif Systems" (takes a few minutes).
  • 3. Plug the ESP32 into your laptop with the USB cable.
  • 4. Tools → Board → esp32 → choose ESP32 Dev Module. Then Tools → Port → pick the new port that appeared when you plugged in (Windows: COM3/COM4...; macOS: /dev/cu.usbserial-...).
  • 5. If no port appears: you need the USB driver (CP210x or CH340 depending on the board: search the exact name printed on the board's USB chip, install, replug). This is the single genuinely annoying step; we do it together in class.
  • 6. The IDE window is your sketch. The ✓ button checks the code; the → button uploads it to the board. After upload, the board runs the code forever, even without the IDE open.
  • 7. The Serial Monitor (magnifying-glass icon, top right) is the window where the board's numbers appear: set its baud rate to 115200 (bottom-right dropdown) to match our code.

04First signal: a touch pin (no breadboard needed)

  • Wiring: clip one jumper wire into the pin labeled 4 (GPIO4 = touch pin T0). Tape the other end to a strip of copper tape on the table. Done: one wire.
  • In the Arduino IDE, paste this, press → to upload, then open the Serial Monitor:
arduino / esp32
void setup() {
  Serial.begin(115200);
}

void loop() {
  int v = touchRead(T0);   // GPIO4: the wire + copper tape
  Serial.println(v);
  delay(30);
}

Numbers stream. Touch the copper: the number drops. That falling number is your entire interface.

05Distance with the HC-SR04

  • Wiring, four jumpers from the sensor's four pins: VCC → 5V pin on the ESP32 (labeled 5V or VIN), GND → GND, TRIG → pin 5, ECHO → pin 18. Push the sensor into the breadboard facing outward so it can "see."
arduino / esp32
const int TRIG = 5, ECHO = 18;

void setup() {
  Serial.begin(115200);
  pinMode(TRIG, OUTPUT);
  pinMode(ECHO, INPUT);
}

void loop() {
  digitalWrite(TRIG, LOW);  delayMicroseconds(2);
  digitalWrite(TRIG, HIGH); delayMicroseconds(10);
  digitalWrite(TRIG, LOW);
  long d = pulseIn(ECHO, HIGH);
  float cm = d * 0.0343 / 2.0;
  Serial.println(cm);
  delay(50);
}

Upload, open Serial Monitor, wave your hand: centimeters stream out.

06Pressure with the FSR

  • Wiring: one FSR leg into a breadboard row fed by 3.3V. The other leg into a new row; from that same row, one jumper to pin 34 and the 10 kΩ resistor to the − rail (GND). This resistor pair is called a voltage divider: it turns squeeze into a readable voltage.
  • Code: replace the loop with Serial.println(analogRead(34)); (keep Serial.begin(115200); in setup). Press the FSR: the number climbs.

08OSC over Wi-Fi to TouchDesigner

For installations, skip the USB cable: the ESP32 joins the Wi-Fi and sends OSC messages (Arduino IDE → Library Manager → install ArduinoOSC: its examples show the ten lines: your Wi-Fi name, password, the laptop's IP, and a message like /sensor/distance with the value). In TD: add an OSC In CHOP, set the port to match (8000), and the value appears as a channel: → Lag → Math → drag onto any parameter → Export: the exact demo 07 move with the LFO swapped for the world. A mapped surface from demo 09 plus a presence sensor is a piece that notices its audience.

09Smooth it

Sensor values are noisy. Smooth in software: val = lerp(val, newVal, 0.1) in p5, a Lag CHOP in TD. Raw sensor data always looks broken; smoothed data looks intentional.
